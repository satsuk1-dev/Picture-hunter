# gitの使い方・チームルール

このドキュメントは、チームでgitを使って開発するときの「これだけ守れば大丈夫」というルールをまとめたものです。迷ったらここを見てください。

## 基本の考え方

- **共有リポジトリ**(GitHubなど): みんなの元データ
- **ローカルリポジトリ**(自分のPC): 自分専用の作業コピー
- 自分のPCで作業して、変更を共有リポジトリに送る(push)ことで、チームの成果が1つにまとまります。

## 守るルール(5つだけ)

1. **`main` ブランチでは直接作業しない。** 必ず自分用のブランチを作って作業します。(mainが壊れるとチーム全員が困るため)
2. **作業を始める前に、必ず `git pull` をする。** (他の人の変更を取り込まないと、あとで衝突しやすくなるため)
3. **変更は「プルリクエスト(PR)」で提出し、自分以外の1人が確認してからマージする。** (ミスに気づきやすくなり、お互いの作業内容も共有できるため)
4. **パスワード、APIキー、秘密鍵などはコミットしない。** (一度公開すると取り消せないため)
5. **困ったら、1人で抱え込まずにすぐ相談する。** エラーメッセージはそのままチームのチャットに貼ってください。

## 作業の流れ

### 1. 最新の状態にして、作業用ブランチを作る

```bash
git switch main
git pull
git switch -c feature/作業名
```

### 2. ファイルを編集する

### 3. 変更を確認して、コミットする

```bash
git status                  # 何が変わったか確認
git add .                   # 変更をコミット対象にする
git commit -m "ログイン画面を追加"
```

### 4. 共有リポジトリに送る(push)

```bash
git push -u origin feature/作業名
```

2回目以降は `git push` だけで構いません。

### 5. プルリクエスト(PR)を作る

1. GitHubのリポジトリページを開く
2. 「Compare & pull request」ボタンを押す
3. 何を変更したか、簡単に説明を書く
4. レビュー担当(自分以外のメンバー)を指定して作成する

### 6. レビューを受けて、マージする

- レビューで指摘があれば、同じブランチで修正して再度pushします。
- 確認(Approve)をもらったら、GitHub上でマージします。
- マージしたら、次の作業の前に `git switch main` → `git pull` で最新にします。

## ブランチ名のルール

`種類/作業内容` の形で、英語(小文字)とハイフンで書きます。

| 種類 | 使う場面 | 例 |
| --- | --- | --- |
| `feature/` | 新しい機能を作る | `feature/login-page` |
| `fix/` | 不具合を直す | `fix/button-error` |
| `docs/` | 文書を書く・直す | `docs/readme-update` |

## コミットメッセージのルール

- 「何をしたか」が分かるように、短く書きます。
- 1つのコミットでは、1つのまとまった変更だけにします。

```
良い例: ログイン画面を追加
良い例: 登録ボタンの表示崩れを修正
悪い例: 更新
悪い例: あああ
```

## よく使うコマンド一覧

| やりたいこと | コマンド |
| --- | --- |
| 今のブランチと変更状況を見る | `git status` |
| 最新の内容を取り込む | `git pull` |
| ブランチを作って移動する | `git switch -c ブランチ名` |
| ブランチを移動する | `git switch ブランチ名` |
| 変更をコミット対象にする | `git add .` |
| コミットする | `git commit -m "メッセージ"` |
| 共有リポジトリに送る | `git push` |
| 履歴を見る | `git log --oneline` |

## 困ったときは

| 状況 | 対処 |
| --- | --- |
| 間違ってmainで編集してしまった | コミットする前なら、そのまま `git switch -c feature/作業名` でブランチを作れば、変更を引き継げます。コミットしてしまった場合は、pushする前にリーダーに相談してください。 |
| `Authentication failed` と出る | パスワードではなく、パーソナルアクセストークン(またはSSHキー)が必要です。 |
| `Repository not found` と出る | URLの間違い、またはリポジトリへの招待が未承認の可能性があります。 |
| コンフリクト(変更の衝突)が起きた | 無理に解決せず、リーダーかチームに相談してください。 |
| よく分からなくなった | 作業をいったん止めて、`git status` の結果をチームに共有してください。 |

## チームの約束

- 作業を始める前に、チャットで「何をやるか」を一言共有する。
- PRのレビューは、できるだけ当日か翌日までに行う。
- 失敗しても大丈夫。gitは履歴が残るので、たいてい元に戻せます。慌てずに相談しましょう。
